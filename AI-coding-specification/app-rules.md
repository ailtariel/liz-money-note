# App 规则

本文档是 Liz Money Note 的仓库级 App 规则，适用于业务功能、UI 文案、信息架构和移动端产品形态相关的代码修改。

具体设计细节和页面说明放在 `docs/design/` 下；本文档只保留对实现有约束力的 App 规则。

## 产品形态

- 本项目是 Android 优先的移动端记账 App。
- 这是移动端产品，不是 PC 页面适配移动端。
- 不新增 PC 管理后台式页面。
- 不额外引入 UI 框架。

实现优先级：

1. 快速查看流水。
2. 快速新增流水。
3. 单手操作。
4. 降低信息密度。
5. 减少点击次数。

页面不应呈现为 Excel、数据库、ERP、CRM、Admin Dashboard 或后台管理系统风格。

## 用户可见文案

- UI 文案必须支持 i18n。
- 当前仅支持 `zh-cn` 和 `en`。
- 页面、导航、按钮、表单标签、空状态、错误提示等用户可见文案应通过 i18n key 管理。

## 导航和入口

- 一级导航固定为 4 个入口：流水、统计、资产、更多。
- 不把新增流水入口放到底部导航。
- 流水页的新增流水入口放在底部导航上方正中，作为页面主操作，不计入底部导航入口。
- 不让底部导航横向滚动。
- 底部导航不超过 5 个入口。
- 新增流水是最高频操作，当前作为全屏 Dialog 打开，不作为独立路由。

## 页面设计约束

- 流水列表不使用 data table、表格列或分页。
- 不出现桌面表格结构，例如“日期 | 类型 | 账本 | 账户 | 金额 | Tag”。
- 列表中不直接显示 ID、创建时间、更新时间、删除按钮、编辑按钮或三点菜单。
- 统计页面只展示核心指标，不堆叠大量报表。
- 资产页面使用卡片形式，不使用表格。
- 低频功能放入更多页面。

## 数据和安全边界

- 系统清理缓存可以清理浏览器 CacheStorage 和 Android WebView 缓存。
- 系统清理缓存不得删除 SQLite 业务数据、导入数据、账本、账户、流水或用户偏好。
- 金额统一使用货币代码展示，不混用本地货币符号。
- 日期组件内部 Date 对象不应直接泄露为业务存储格式；保存前应统一转换为业务层约定格式。

## 代码组织约束

- 带较多数据业务、领域状态、筛选逻辑、数据加载或业务交互的功能页面和功能内组件应放在对应 `src/modules/<feature>/` 下。
- `src/modules/<feature>/` 可以同时包含领域类型、repository、service、store、feature composable、页面入口和该功能私有组件，但职责仍应清晰分层。
- `src/components/` 只放轻量纯 UI 组件、应用级页面壳、跨功能展示组件，或不持有领域数据业务的组件。
- 通用共享组件放在 `src/components/shared/`。
- 只有被多个功能复用且不绑定单一业务领域时，组件才放在 shared。
- 不再新增 `src/pages/` 页面入口。
